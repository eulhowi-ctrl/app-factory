# 정책·리스크 노트

> 공장 전체를 지키는 방패. 여기 적힌 것을 어기면 계정 단위 제재까지 갈 수 있다.

## 1. Google Play 스팸 정책 (최대 리스크)
- **무검수 대량 출시는 "스팸"으로 간주되어 계정 전체가 제재**될 수 있다.
- 장삼식(하루 2~3개) 전략을 그대로 따라가면 안 된다. **주 1개 + 검수 게이트**를 못 박는다.
- 한 앱의 품질이 다음 앱의 승인에 영향을 준다 → **품질은 공장의 브랜드**.

## 2. 절대 자동화 금지 목록 (품질 방패)
1. 소재(니치) 최종 선택 — 인간. 여기서 실수하면 파이프라인이 전부 헛일.
2. 검수 게이트 — 빌드 성공 ≠ 상장 가능. 사람이 기능 확인.
3. 서명 키/자격증명 — 절대 스크립트·커밋에 넣지 않음.
4. Play Console 제출 — 수동 (클로즈드 테스트 12명은 실제 사람 필요).
5. 콘텐츠 품질 — AI 산출물을 무검수로 올리지 않음.

## 3. 서명 키 (분실 = 업데이트 불가)
- `upload.keystore` + `keystore.properties`는 `.gitignore` 필수.
- **클라우드 + USB 이중 백업**. 분실하면 기존 사용자에게 업데이트를 영원히 못 준다.
- Play App Signing 사용 시 업로드 키만 보관하면 됨.

## 4. Windows 환경 함정
- PowerShell에서 `.\gradlew.bat` (유닉스 `./gradlew` 아님)
- `ANDROID_HOME = %LOCALAPPDATA%\Android\Sdk` 설정
- 에뮬레이터 가속: BIOS에서 가상화(VT) 활성화 — 안 되면 실기기/Pre-launch report로 대체
- **한글 경로/사용자명은 Gradle 오류 유발** → 프로젝트 경로 영문 유지

## 5. AdSense vs AdMob
- 웹 AdSense: 니치 툴 사이트(단일 기능, AI 생성)는 사실상 승인 불가 → 웹 수익화 포기.
- 안드로이드 AdMob + "광고 제거" IAP가 현실적 수익원. 구독은 "지속 가치"(데이터 동기화, 알림 등)가 있는 앱만.

## 6. 현실적 수익 기대
- 니치 툴 광고 수익은 소액이다. 이 전략의 진짜 가치는:
  **"안정적으로 작동하는 파이프라인 + 유통 채널(커뮤니티 테스터)"**
- 10개 중 일부만 히트해도 개발비가 회수되는 구조. 초기 몇 개는 지표 수집이 목적.

## 7. 비용·토큰 관리
- 주 1개 루프는 클로드 토큰 비용이 실재. 한 세션에서 PRD→골격→기능 집중으로 효율 유지.
- 계정 개설 초기비용: Play $25 + 도메인 ~$11 ≈ **$40 미만** (Cloudflare·AdMob 무료).
