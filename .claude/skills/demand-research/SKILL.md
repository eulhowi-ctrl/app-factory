# 수요 발굴

## 출력
- `apps/_candidates/YYYY-MM-DD-candidates.md` (폴더가 없으면 생성)

## 절차

1. **소스 스캔** (WebSearch/WebFetch 병행, 최소 3개 소스 이상):
   - Reddit: `r/AppIdeas`, `r/smallbusiness`, `r/productivity`, 관련 업종 커뮤니티 — "wish there was an app/tool for..." 신호
   - Hacker News "Ask HN: what tool do you wish existed?"
   - ProductHunt 리뷰·요청 글
   - 앱스토어 리뷰의 불만·기능 요청 신호
2. **후보 10~15개** 선별. 각 후보에 반드시 포함:
   - `문제`: 한 문장
   - `증거`: 원문 링크 2~3개 (없는 후보는 버린다)
   - `경쟁`: 기존 앱 존재 여부 + 왜 불만족인지
   - `수익`: 광고/일회결제 의지가 보이는지
   - `난이도`: 주 1개 생산에 가능한지 (서버 없이 가능? 기능 수?)
   - `플랫폼`: 웹/안드로이드 어느 쪽이 유리한지
   - `지역·언어`: 틈새 지역 여부
3. **채점**: 각 후보 1~5점 = (증거 확실성 + 수익성 + 난이도) 종합. 상위 3개를 "인간 추천"으로 표시.
4. **인간 선택 요청**: 후보 목록을 보여주고 "어느 것으로 갈까요?" 질문. 스스로 선택하지 않는다.

## 금지
- 증거 링크 없는 아이디어 나열 금지
- 최종 선택을 AI가 단독 결정 금지 (선택은 인간 몫)
- 후보가 10개 미만이면 소스를 더 돌린다 (성급한 마감 금지)
